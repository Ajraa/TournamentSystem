Popis tématu

Co je OAuth 2.0?

OAuth 2.0 je otevřený autorizační protokol (RFC 6749), který umožňuje aplikacím získat omezený přístup k uživatelskému účtu na jiné službě — bez sdílení hesla. Uživatel schvaluje přístup přímo na straně poskytovatele (Google, GitHub…).

Bezpečnost

Aplikace nikdy nevidí heslo uživatele. Přístupové tokeny mají omezenou platnost a scope.

Pohodlí

Jeden klik — žádná registrace, žádné zapomenuté heslo. Uživatel používá svůj Google účet.

Standard

Podporuje ho Google, Facebook, GitHub, Microsoft a další. Používá ho většina moderních webů.

Delegace

Aplikace může dostat přístup k emailu, profilu, kalendáři — jen to, co uživatel schválí.

Jak to funguje

OAuth 2.0 Authorization Code Flow

  1. Uživatel klikne na „Přihlásit přes Google"
  2. Aplikace přesměruje na Google autorizační server s client_id a scope
  3. Google zobrazí consent screen — uživatel schválí přístup
  4. Google vrátí jednorázový Authorization Code na callback URL
  5. Server vymění kód za Access Token (+ ID Token) pomocí client_secret
  6. Access Token slouží k načtení profilu z Google API
  7. Aplikace vytvoří/přihlásí lokálního uživatele
Prohlížeč
↕ přesměrování (redirect)
Google OAuth Server

Django Backend
↕ GET /userinfo
Google People API

client_secret putuje pouze server ↔ server, nikdy přes prohlížeč

Stávající stav

Autentizace v Django bez OAuth

Tradiční Django autentizace pracuje s uživatelským jménem a heslem uloženým v databázi:

# Klasická Django autentizace
from django.contrib.auth import authenticate

user = authenticate(
    request,
    username="uzivatel",
    password="heslo123"
)
if user is not None:
    login(request, user)

Hesla jsou hashována (PBKDF2), ale aplikace musí sama řešit registraci, reset hesla, ověření emailu, brute-force ochranu…

Nevýhody vlastní autentizace

Správa hesel, reset, 2FA, phishing, nutnost ukládat citlivá data v DB

Výhody OAuth2 přes Google

Žádná hesla v DB, Google řeší 2FA a bezpečnost, jednodušší UX, méně kódu k udržení

models.py (zkráceno)

class Player(models.Model):
    user = models.OneToOneField(
        settings.AUTH_USER_MODEL,
        related_name='player_profile'
    )
    fname = models.CharField(max_length=50)
    lname = models.CharField(max_length=50)

class Team(models.Model):
    name    = models.CharField(max_length=20)
    tag     = models.CharField(max_length=3)
    players = models.ManyToManyField(Player)

Řešení

Přístupová ochrana — dekorátory

Vlastní dekorátory v decorators.py chrání views před neoprávněným přístupem:

def player_required(view_func):
    @wraps(view_func)
    def wrapper(request, *args, **kwargs):
        if not request.user.is_authenticated:
            return redirect('account_login')
        if hasattr(request.user,
                   'founder_profile'):
            return redirect('founder_dashboard')
        if not hasattr(request.user,
                      'player_profile'):
            return redirect('role_select')
        return view_func(request, *args, **kwargs)
    return wrapper

Použití v views.py:

@player_required
def player_dashboard(request):
    ...

@founder_required
def founder_dashboard(request):
    ...

Závěr

Výsledek a vlastní názor

Projekt demonstruje kompletní OAuth2 flow s Google API v Django aplikaci. Turnajový systém umožňuje správu hráčů, týmů, turnajů a zápasů, přičemž veškerá autentizace probíhá přes Google.

„OAuth2 přes Google je z pohledu vývojáře výrazně pohodlnější než vlastní autentizační systém — odpadá správa hesel, hashování, reset flow a email verifikace. Knihovna django-allauth celý proces abstrahuje do několika řádků konfigurace. Největším úskalím byla správná volba závislostí (PyJWT vs jwt) a pochopení, jak allauth řeší kolize emailů mezi poskytovateli. Pro školní i komerční projekty doporučuji OAuth2 jako první volbu pro autentizaci."

Co funguje dobře

Jednoduchá integrace, bezpečné uložení credentials, automatická správa tokenů

Omezení

Závislost na Google API, nutnost Google Cloud Console, callbacks pouze přes HTTPS v produkci
